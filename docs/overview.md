# 概要

## 目的

Notion の「進行中タスク」を macOS メニューバー常駐アプリで即時確認・更新できるようにする。

## ゴール

- メニューバーから小窓を開き、進行中タスク一覧を表示する
- タスクを「完了」または「中断」に更新できる
- ローカル完結（サーバ/アプリ内DBなし）

## 非ゴール

- チーム共有・複数ユーザー対応
- オフラインでのタスク編集
- Notion 以外の連携

## 対象ユーザー / ユースケース

- 個人のタスク管理者
- すぐに「今やること」を見たい、完了を即反映したい人

## 主要機能

- Notion 連携設定（トークン/Database ID/Status値 ※更新用・UI非表示）
- 進行中タスク取得・表示
- 完了/中断の更新
- 手動リフレッシュ / 自動更新
- 失敗時の通知と再試行

## 前提 / 仮定 / 未決事項

### 前提

- Notion のタスクは Database で管理されている
- Notion API は Data Source を前提とする最新仕様を使用する（API Version を固定）
- Database は Integration と共有済み

### 仮定

- 進行中/完了/中断の状態値は Notion 側に存在する
- 画面上に Status を表示しない（デフォルトは「進行中のみ」表示）
  - v2 で、期日が今日以前・直近 7 日の未完了タスクも表示する（下記「v2: 今日の絞り込みと習慣の週集計」）

### 決定事項

- 中断タスクの「戻す」はメニューから「中断一覧」へ一時切替して実行する

## v2: 今日の絞り込みと習慣の週集計

- 作成日: 2026-11-12
- 状態: 要件定義（draft）
- 影響範囲の分析: `.claude/docs/impact-analysis/2026-11-11_task-focus-and-habit-streak.md`（作業メモ）

### 背景・目的

日々の利用で次の 3 つの困りごとがある。

- やり忘れに気づけない（期日を過ぎたタスクや、今週の目標に届かない習慣が見えない）
- 今やることが絞れない（進行中が最終編集順に並ぶだけで、期日と優先度が分からない）
- やった実感・振り返りがない（習慣の達成が積み上がって見えない）

### 対象ユーザー

- 本人のみ（自分の Notion 運用に合わせてよい。ただし設定で指定できる形を保ち、値を直書きしない）

### スコープ

#### In Scope

- 期日のある未完了タスクの表示（期限切れ・今日・直近 7 日）と並び順
- 未着手タスクを進行中にする操作
- メニューバーの件数表示
- 習慣の連続達成週数と今週の達成状況、目標に届かなくなりそうな習慣の強調

#### Out of Scope（2026-11-12 本人と合意）

- タイマー・作業時間の計測（Notion のオートメーションがステータス変更で記録しているため）
- グローバルホットキー（ADR-0006）、クイックキャプチャ（ADR-0009）、中断タブ（ADR-0004）の復活
- 期日の先送り、今日完了したタスクの一覧、「今の 1 件」の固定、進行中の上限警告
- Webhook による即時反映（サーバが必要）

#### 将来検討

- プロジェクト（Relation）の表示と絞り込み
- 習慣の「トリガー」（起床後・昼食後など）でのまとまり表示（習慣 DB に Select がある）
- 習慣の月単位の表示（ヒートマップ）
- 通知（ネイティブ通知は署名が必要で、現在の配布形態では使えない。署名して配布する場合に検討する）

| 未着手タスク         | 未完了タスクのうち、ステータスが「進行中」でないもの                                                   | 待ち・確認中・保留                                                       |
| 期日                 | タスクの期日プロパティの日付。期間で入っている場合は終了日                                             | 時刻付きの値はローカル時刻に直してから日付の部分だけで比べる             |
| 今日                 | Mac のローカルタイムゾーンでの当日                                                                     |                                                                          |
| 期限切れ             | 期日が今日より前の未完了タスク                                                                         |                                                                          |
| 今日のタスク         | 期日が今日の未完了タスク                                                                               |                                                                          |
| 直近 7 日のタスク    | 期日が明日から今日＋7 日までの未着手タスク                                                             |                                                                          |

| 習慣ページ           | 習慣 DB の 1 ページ。1 つの習慣の 1 週分を表す                                                         | 毎週日曜の未明に自動で作られる                                           |

| 達成週               | その週の習慣ページで、チェックの数が N 以上の週                                                        |                                                                          |
| 連続達成週数         | 先週から過去へ遡り、達成週が続いた数。今週がすでに達成週なら今週も足す                                 | 暦で 52 週前まで遡る。ページが無い週とゴールが読めない週は数えずに飛ばす |
| 今週の残り日数（D）  | 今日を含めた、今週の残りの日数                                                                         | 日曜は 7、土曜は 1                                                       |
| 今週の残り回数（R）  | N から今週のチェック数を引いた数                                                                       |                                                                          |

### 機能要件

#### FR-01: 期日タスクの表示

- 対応機能: FT-01 / 優先度: Must
- ユースケース
  1. 利用者がメニューバーから小窓を開く
  2. 期限切れと今日のタスクが、進行中タスクより上にまとまって見える
- 受け入れ条件
  - [ ] 期日が今日より前の未完了タスクは、ステータスが待ち・確認中・保留・進行中のどれでも「期限切れ」として表示される
  - [ ] 期日が今日の未完了タスクは「今日」として表示される
  - [ ] ステータスが完了・中断のタスクは、期日にかかわらず表示されない
  - [ ] 期日が期間のタスクは、終了日で判定される
  - [ ] 期日が無い、または明日以降の進行中タスクは、「進行中」のまとまりに表示される（期日があれば期日も表示する）
  - [ ] 1 つのタスクは 1 つのまとまりにだけ表示される。期限切れ → 今日 → 進行中 → 直近 7 日（FR-03）の順に、最初に当てはまったまとまりに入る
  - [ ] 期限切れのタスクは、ほかのタスクと見た目で区別できる（色や印）
  - [ ] 期限切れ・今日のタスクには期日が表示される
  - [ ] 条件に合うタスクが 100 件を超えても、すべて対象になる（取得件数の上限で欠けない）
  - [ ] 期日プロパティ、または完了・中断のステータス値が設定されていないタスク DB では、これまでどおり進行中タスクだけが表示される
  - [ ] まとまりへの振り分けは、取得したときではなく表示・件数更新のたびに、その時点の今日を基準に行う

#### FR-02: タスクの並び順

- 対応機能: FT-02 / 優先度: Must
- 受け入れ条件
  - [ ] 一覧は、期限切れ → 今日 → 「進行中」の順のまとまりで表示される。FR-03 を実装する場合は、その後に「直近 7 日」が続く
  - [ ] 期限切れのまとまりは、期日の古い順に並ぶ
  - [ ] 同じまとまりの中で期日が同じタスクは、優先度の高い順（高 → 中 → 低 → 未設定）に並ぶ
  - [ ] 優先度も同じタスクは、最終編集の新しい順に並ぶ
  - [ ] 優先度の高い順は設定で決められ、Notion の選択肢の並び順に依存しない
  - [ ] 「進行中」のまとまりは、優先度の高い順、次に最終編集の新しい順に並ぶ（期日では並べない）

#### FR-03: 直近 7 日のタスク

- 対応機能: FT-03 / 優先度: Should
- 受け入れ条件
  - [ ] 期日が明日から今日＋7 日までの未着手タスクが、「直近 7 日」のまとまりに表示される（進行中のタスクは「進行中」のまとまりに出るので、ここには出さない）
  - [ ] 「直近 7 日」は期日の近い順に並び、期日が同じなら FR-02 と同じ優先度順になる
  - [ ] 「直近 7 日」のタスクには期日が表示される
  - [ ] 「直近 7 日」のタスクは、メニューバーの件数（FR-05）に数えない

#### FR-04: 「開始」操作

- 対応機能: FT-04 / 優先度: Should
- ユースケース
  1. 利用者が期限切れの「待ち」のタスクを見つける
  2. 「開始」を押すと、そのタスクのステータスが進行中になる
- 受け入れ条件
  - [ ] 未着手タスク（待ち・確認中・保留）に「開始」の操作がある
  - [ ] 「開始」を押すと、Notion 上のステータスが進行中の値に変わる
  - [ ] 進行中タスクには「開始」の操作が出ない
  - [ ] 未着手タスクにも「完了」と「Notion で開く」の操作がある
  - [ ] 失敗したら一覧の状態は変わらず、小窓に失敗のエラー表示（既存の完了・中断の失敗時と同じ形式）が出る

#### FR-05: メニューバーの件数

- 対応機能: FT-05 / 優先度: Should
- 受け入れ条件
  - [ ] メニューバーのアイコンの横に「⚠{期限切れ＋今日のタスク数} ✓{残っている習慣の数}」が表示される
  - [ ] 「残っている習慣」は、今週の習慣ページがあり、今日のマスが未チェックで、今週の目標回数にまだ届いていない習慣。目標回数が読めない習慣は、今日のマスが未チェックなら数える
  - [ ] 起動してから最初の取得が終わるまでは、アイコンだけを表示する
  - [ ] タスク DB・習慣 DB が複数有効なときは、それぞれの種類ごとに合算する
  - [ ] 0 の項目は表示しない。両方 0 ならアイコンだけになる
  - [ ] 直近の取得で 1 つでも DB の取得に失敗したら、件数を消して「!」だけを表示する
  - [ ] 次の取得に成功したら、件数の表示に戻る
  - [ ] ポーリングの結果が、取得完了から 1 秒以内に反映される
  - [ ] 小窓での「完了」「中断」「開始」、習慣のチェックの後、再取得が終わったら件数が更新される
  - [ ] 日付が変わったら、次のポーリングの結果で今日の基準が切り替わる

#### FR-06: 習慣の週集計

- 対応機能: FT-06 / 優先度: Must
- ユースケース
  1. 利用者が習慣タブを開く
  2. 今日の未チェック習慣の一覧（従来どおり）の下に、全習慣の今週の状況が並ぶ
- 受け入れ条件
  - [ ] 今週の習慣ページがある習慣ごとに 1 行が表示される
  - [ ] 各行に、習慣名・今週 7 マス（日〜土のチェック状態）・今週のチェック数と目標回数（例: 2/3）・連続達成週数が表示される
  - [ ] 今日のマスが分かるように表示される
  - [ ] 連続達成週数は、先週から過去へ遡って達成週が続いた数に、今週が達成週なら 1 を足した数になる
  - [ ] 習慣ページが無い週は、連続を途切れさせずに飛ばす
  - [ ] 習慣の同一性は習慣名で判定する。同じ週に同じ名前のページが複数あるときは、作成日時が最も新しい 1 件を使う
  - [ ] 今週の習慣ページがまだ作られていない間（日曜未明など）は、週集計も今日の一覧も空にし、前の週のページで代用しない
  - [ ] 曜日チェック列の設定が日〜土の 7 列そろっていない習慣 DB では、週集計（FR-06・FR-07）を無効にし、v1 と同じ表示にする
  - [ ] 過去の週のデータは、起動時・日付が変わったとき・手動更新のときに取り直す。今週のデータは毎回のポーリングで取る
  - [ ] 過去の週のチェックを後から変えた場合、連続達成週数への反映は次に過去の週を取り直したとき（翌日か手動更新）でよい
  - [ ] ゴールが空、または「週N回」として読めない習慣は、7 マスとチェック数だけを表示し、目標回数と連続達成週数は表示しない
  - [ ] 「ゴール」は「週１回」のような全角数字でも「週1回」のような半角数字でも読める
  - [ ] 今日の未チェック習慣の一覧（従来の表示）は、今週の習慣ページだけを対象にする。先週のページを今週分として表示しない
  - [ ] 遡るのは今週から暦で 52 週前までとする。その範囲で一度も途切れず、かつ 52 週前の週にもその習慣のページがある場合は「52+」と表示する（過去のページがそこまで無いなら、数えた値をそのまま出す）
  - [ ] 過去の週でゴールが読めないページは、ページが無い週と同じく飛ばす

#### FR-07: 目標が危ない習慣の強調

- 対応機能: FT-07 / 優先度: Should
- 受け入れ条件
  - [ ] 今日のマスが未チェックで、R = D の習慣は「今日やらないと届かない」として強調される
  - [ ] 今日のマスが未チェックで、R > D の習慣は「今週は届かない」と分かる表示になる（強調はしない）
  - [ ] 今日のマスがチェック済み、または R ≤ 0 の習慣は強調されない
  - [ ] 強調は、今日の未チェック習慣の一覧と、週集計の両方に出る
  - [ ] 目標回数が読めない習慣は強調の対象にしない
  - judge: 「強調」は、強調しない行と並べたときに、色と印（例: 赤系の色＋「!」）の両方で区別できること。「今週は届かない」は、強調と別の見た目（例: 薄い表示）で区別できること

#### FR-08: v2 の設定項目

- 対応機能: FT-08 / 優先度: Must
- 受け入れ条件
  - [ ] タスク DB ごとに、期日のプロパティと優先度のプロパティを設定画面で選べる（既存のプロパティ自動取得の候補から選ぶ）
  - [ ] 優先度の選択肢を、高い順に並べて保存できる（例: 高 → 中 → 低）。未設定なら優先度では並べない
  - [ ] 習慣 DB ごとに、ゴールのプロパティを設定画面で選べる
  - [ ] どれも空欄のまま保存でき、空欄なら該当機能が無効になる（NFR-02）
  - [ ] 保存した値は `config.json` に保存され、次の起動でも使われる

### 非機能要件

#### NFR-01: API 呼び出し — レート上限の順守

- 優先度: Must
- 要件: Notion API の上限（平均 3 リクエスト/秒）に対し、手動操作の分の余裕を残すため、アプリが自動で出すリクエストは平均 1 リクエスト/秒以下にする。習慣の過去分（連続達成週数用）は毎回のポーリングでは取らない（FR-06）
- 計測基準: 平常時（タスク DB・習慣 DB 各 1、手動操作なし）のリクエスト数をログで数え、どの 1 分間でも 60 件以下。過去分を取り直す 1 分間も含む

#### NFR-02: 互換性 — 既存設定のまま動く

- 優先度: Must
- 要件: 既存の `config.json` をそのまま読み込める。期日・優先度・ゴールのプロパティが未設定なら、該当機能は無効になり、v1 と同じ表示になる
- 計測基準: v1 の設定ファイルで起動し、タスク一覧が進行中のみ、習慣一覧が未チェックのみになることをテストで確認する

#### NFR-03: 時刻の基準 — ローカルタイムゾーン

- 優先度: Must
- 要件: 「今日」「週」「習慣ページの週」は Mac のローカルタイムゾーンで判定する
- 計測基準: タイムゾーンを固定したテストで、日付の境界（23:59 / 0:00）と週の境界（土曜 23:59 / 日曜 0:00）の判定を確認する
- 既知の制約（2026-11-12 本人が受容）: 習慣ページは日本時間の日曜未明に作られる。Mac のタイムゾーンを日本以外にすると、習慣ページの週が 1 週ずれることがある

#### NFR-04: 表示の鮮度 — 古い件数を出し続けない

- 優先度: Should
- 要件: メニューバーの件数は、直近の取得が失敗していたら表示しない（FR-05）。小窓の一覧は、失敗時も前回の結果を出してよい（ADR-0010 のまま）
- 計測基準: 取得を失敗させたテストで、ラベルが「!」になり、一覧は前回の結果のままになることを確認する

#### NFR-05: 性能 — 取得にかかる時間

- 優先度: Should
- 要件: 1 回のポーリング（全 DB、過去分を含まない）は 10 秒以内に終わる。過去分の取り直しは 30 秒以内に終わり、その間も一覧とメニューバーは前の結果で操作できる
- 計測基準: 実際の DB（タスク・習慣各 1）で、ログに出る開始・終了時刻の差を測る

#### NFR-06: 診断 — 失敗の原因が分かる

- 優先度: Should
- 要件: 取得に失敗したら、DB 名・失敗の種類（権限・未共有・レート制限・通信など）をログに残す。小窓には、最後に失敗した時刻と失敗の種類を出す。トークンはログに出さない（既存方針）
- 計測基準: 401・404・429・タイムアウトを起こしたテストで、ログと小窓に失敗の種類が出ることを確認する

### 前提 / 確認事項

- タスク DB の期日は「期限日」（Date）、優先度は「優先度」（Select: 低・中・高）、習慣 DB の目標は「ゴール」（Select: 週１回〜週７回）。プロパティ名はいずれも設定で指定する
- Notion API からステータスを進行中に変えたとき、作業時間を記録する Notion のオートメーションが動くかは未確認（実装時に確かめる）
- Select 型のステータスで、値が空のページが「完了でない」の条件に当たるかは未確認（今の DB は Status 型なので影響しない。実装時に確かめる）

### 既存 ADR への影響

基本設計で ADR-0013 を起こし、次の既存 ADR を更新する（置き換えではなく、該当項目の改訂として扱う）。

| ADR      | 変わる点                                                                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADR-0004 | 「進行中タスクの確認」に集中する方針に、期日のある未完了タスクの表示を加える。中断タブ廃止は維持する                                                                      |
| ADR-0007 | 項目 4「過去分は表示しない」を、今日の一覧については維持し、週集計（FR-06）では過去 52 週を読むように改める。「最新 1 件」の判定を「今週のページのうち最新 1 件」に改める |
| ADR-0010 | 「取得失敗時はキャッシュを維持」を、小窓の一覧については維持し、メニューバーの件数は例外とする（NFR-04）                                                                  |
