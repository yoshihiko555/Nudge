# ADR-20261112-0014: 習慣は週単位で扱い、週は作成日時で判定し、「週N回」を達成した週の連続を数える

- ステータス: 採用
- 決定日: 2026-11-12
- 関連: [ADR-0007](0007-multi-db-habit-tabs.md) の「決定」4（習慣名ごとに最新 1 件を出し、過去分は表示しない）を一部置き換える。習慣タブの見せ方は [ADR-20261112-0016](ADR-20261112-0016-habit-row-merge.md) で決めた。[ADR-20261112-0015](ADR-20261112-0015-tray-count-label.md) が、この ADR の「決定」2 の達成週の判定と「決定」3 の今日の対象を件数に使う

## 背景

本人の習慣 DB の作りは次のとおり（2026-11-12 に Notion のデータソースの定義と実際のページで確認）。

- 1 ページが「1 つの習慣の 1 週分」で、曜日のチェックの列は日〜土の 7 つ。
- 目標は Select「ゴール」で、値は「週１回」〜「週７回」（全角数字）。
- 週を表す数式「週番号」がある。

実際のデータで分かったことは次のとおり（2026-11-12、本人の DB）。

- **週番号**: 11/8（日）〜11/14 の週のページの値が `2026_45` だった。ISO 週（月曜始まり）で計算していると考えられ、日曜始まりの曜日の列とは 1 日ずれる。数式の中身は API から読めなかった。
- **ページの作成**: 週のページは、日本時間の日曜 0:00〜2:31 に自動で作られていた（作成日時 2026-11-07T15:00Z〜17:31Z）。
- **同名ページ**: 52 週の範囲に 364 ページあり、同じ週に同じ名前のページが 2 つある習慣が実在した。

v1 の作りと、そこで起きていた問題は次のとおり。

- **表示**: 作成日時の新しい順に `max_results` 件を取り、同じ名前の最新 1 件のうち今日の列が未チェックのものだけを出していた。
- **週の初め**: 今週のページがまだ作られていない時間帯は、先週のページを今週分として扱っていた。
- **振り返り**: 過去の週は見られず、「やった実感・振り返りがない」という困りごとがあった（`docs/overview.md` の「v2」の「背景・目的」）。
- **取得の頻度**: v1 は 60 秒ごとに全 DB を取り直していた（ADR-0002・ADR-0010）。連続を数えるのに要る過去 52 週分（本人の DB で 364 ページ）を同じ頻度で取ると、毎回 4 回のページ送りが増える。そのため、連続の数え方と過去の週を取る頻度は一緒に決める。

## 選択肢

### A. 週を「週番号」で判定する（不採用）

- 日曜始まりの曜日の列と 1 日ずれる。数式の中身を API で確かめられない。

### B. 毎日の連続日数を数える（不採用）

- 「週N回」の習慣は毎日やるものではなく、やらない日があるたびに途切れてしまう。

### C. 週を作成日時で判定し、「週N回」を達成した週の連続を数える（採用）

- 週のページは日本時間の日曜未明に作られるので、作成日時の日曜始まりの週で確実に見分けられる。目標の単位（週）と数える単位がそろう。

## 決定

**習慣は週単位で扱う。習慣ページの週は作成日時（ローカル時刻、日曜始まり）で判定し、「週N回」を達成した週が何週続いたかを数える。**

1. **同一性**: 習慣は名前で見分ける。同じ週に同じ名前のページが複数あれば、作成日時が新しい 1 件を使う。
2. **連続の数え方**: 達成週は、その週のチェック数が N 以上の週とする。先週から暦で 52 週前まで遡って、達成週が続いた数を数える。ページが無い週とゴールが読めない週は、途切れさせずに飛ばす。今週がすでに達成週なら 1 を足す。
3. **今日の対象**: 今日の対象は今週のページだけとし、先週のページを今週分として扱わない。
4. **過去の週の取得**: 過去の週は日中に変わらないので、毎回の取得では取らず、起動時・日付の切り替わり・手動更新・設定の変更のときに取る。
5. **対象外の DB**: 曜日の列が 7 つそろっていない DB は、v1 と同じ処理のままにする。

## 検証

- 2026-11-12 に、本人の習慣 DB へ作成日時で絞った問い合わせを送った。今週分は 7 ページ、過去 52 週分は 364 ページ（4 回のページ送り）が返った。
- 単体テストで、次の点を確かめた（`internal/app/habit_summary_test.go`・`internal/app/habit_flow_test.go`）。
  - 週の境界（土曜 23:59 と日曜 0:00、夏時間の切り替わりの週）
  - 同じ週の同名ページ、ページの無い週とゴールが読めない週を飛ばすこと
  - 連続が途切れること、52 週の上限
  - 過去の週を 1 日 1 回だけ取ること
- 2026-11-12 に、本人が実機で習慣タブの表示を確認した。

## 影響

- **良い影響**: 今週の達成状況と連続週数が見える。
- **タイムゾーン**: Mac のタイムゾーンを日本以外にすると、日本時間で作られたページの週が 1 週ずれることがある。本人はこれを受け入れている（`docs/overview.md` の「v2」の NFR-03）。
- **API の呼び出し**: 過去の週を取るたびに、数回のページ送りが増える（1 日 1 回）。
- **未取得のとき**: 過去の週を取れていない間は、連続週数を出せない。

## 決定しないこと

- **習慣の「トリガー」（起床後・昼食後など）でのまとまり表示**: `docs/overview.md` の「v2」の「将来検討」に置く。本人が時間帯ごとに分けたくなったときに決める。
- **月単位の表示（ヒートマップ）**: 同じく「将来検討」に置く。52 週の連続週数では振り返りが足りなくなったときに決める。
- **Mac を日本以外のタイムゾーンで使うときの週の扱い**: 本人が日本以外で使うことになったときに決める。
