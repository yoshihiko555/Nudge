# ADR-20261112-0013: 期日のある未完了タスクを、進行中と並べてまとまりで表示する

- ステータス: 採用
- 決定日: 2026-11-12
- 関連: [ADR-0004](0004-liquid-glass-ui.md) の「理由」の「中断タブの廃止」にある「本来の目的（進行中タスクの確認）に集中させる」を一部置き換える（中断タブの廃止そのものは維持する）。[ADR-0012](0012-settings-ux-and-notion-datasource.md)（設定の汎用化）を前提にする

## 背景

- v1 の小窓は、ステータスが「進行中」のタスクだけを、最終編集の新しい順に `max_results` 件（既定 30 件）まで取得して表示していた。続きのページは取得していなかった（v1 の `internal/notion/client.go` の `QueryByStatus`）。そのため、期日を過ぎた未着手のタスクは小窓に出なかった。
- 利用者は本人 1 人で、「やり忘れに気づけない」「今やることが絞れない」という困りごとがあった（`docs/overview.md` の「v2」の「背景・目的」）。
- 本人のタスク DB には、期日（Date）、優先度（Select: 低・中・高）、ステータス（Status）がある。ステータスの値は、未着手が待ち・確認中・保留、ほかに進行中・完了・中断（2026-11-12 に Notion のデータソースの定義で確認）。
- 取得条件を広げても 30 件で打ち切ると、最終編集の古い期限切れが落ちて、件数も不正確になる。

## 選択肢

### A. 進行中だけのまま、期日を表示に足す（不採用）

- 未着手の期限切れが小窓に出ないので、「やり忘れに気づけない」が解けない。

### B. 取得の上限を 100 件に上げるだけ（不採用）

- 条件に合うタスクが 100 件を超えると、また欠ける。

### C. 期日のある未完了タスクを全件取り、進行中と並べてまとまりで出す（採用）

- 期限切れと今日のタスクが、未着手でも上に出る。続きのページまで取るので欠けない。

## 決定

**期日・完了・中断の値が設定された DB では、期日のある未完了タスクを、進行中と並べて期限切れ・今日・進行中・直近 7 日のまとまりで表示する。**

1. 対象は、ステータスが完了・中断のどちらでもない未完了のタスクで、未着手も含める。期日が期間のときは終了日を使う。
2. まとまりは、期限切れ → 今日 → 進行中 → 直近 7 日の順に並べる。1 つのタスクは、最初に当てはまった 1 つのまとまりにだけ入れる。
3. 「今日」は Mac のローカルタイムゾーンで判定し、表示のたびにその時点の日付で計算し直す。
4. 条件に合うタスクは、件数の上限で欠けないよう続きのページまで取る。安全のために打ち切る上限を超えたら、欠けたことを表示する。
5. 期日・完了・中断の値のどれかが設定されていない DB は、v1 と同じ「進行中のみ」の表示にする。

## 検証

- 2026-11-12 に、本人のタスク DB へこの条件の問い合わせを送った。Notion API（バージョン 2025-09-03）が受け付け、未完了のタスクだけが返った（進行中 2 件・待ち 3 件、完了・中断は含まれない）。
- 単体テストで、次の 3 点を確かめた（`internal/app/task_view_test.go`・`internal/app/sync_state_test.go`）。
  - 日付の境界（昨日〜今日＋8 日）
  - まとまりの振り分けと並び順
  - v1 の設定のままなら v1 と同じ表示になること

## 影響

- **良い影響**: 期限切れと今日のタスクが進行中の上に出て、未着手でも見落とさない。
- **トレードオフ**: 問い合わせがページ送りになり、件数の多い DB では 100 件ごとに呼び出しが 1 回増える。
- **未確認の漏れ**: ステータスが Select 型の DB で値が空のページは、「完了でない」の条件に当たらず漏れる可能性がある（未確認）。本人の DB は Status 型で、値が空にならないので影響しない。
- **設定**: 期日などのプロパティを指定する項目が増える。項目の詳細は `docs/detail-design.md` の「v2」にある。

## 決定しないこと

- **プロジェクト（Relation）での表示と絞り込み**: `docs/overview.md` の「v2」の「将来検討」に置く。本人がプロジェクト別にタスクを分けたくなったときに決める。
- **期日の先送りの操作**: `docs/overview.md` の「v2」の「Out of Scope」に置く。本人が要望したときに決める。
- **Select 型のステータスで値が空のページの扱い**: Select 型のステータスの DB を使うことになったときに、実際の挙動を確かめて決める（`docs/detail-design.md` の「v2」の 2.2）。
